# Meeting

The `Meeting` entity type is defined in [`core/src/data/meeting.ts`](../../../packages/core/src/data/meeting.ts) and its field-naming/type-hierarchy conventions (prefixes, Base/Resolved patterns, key safety) are covered generically in [`core/src/data/spec/README.md`](../../../packages/core/src/data/spec/README.md). See also [GLOSSARY.md](../../../GLOSSARY.md#meeting-model-core--datameeting) for the domain definition. This doc only covers what isn't already obvious from those sources.

## Open questions / gaps

- **`mtDir` is the only required identifier — there is no `mtId`.** Every other entity (`rm`/`ss`/`pr`/`sp`) uses an `*Id`. `mtDir` doubles as both the stable identifier and the directory/key segment (see [`meeting-keys.ts`](../../../packages/core/src/data/meeting-keys.ts)), and [`core/spec/app-env.md`](../../../packages/core/spec/app-env.md) notes `orgDir` is deliberately kept distinct from a meeting id. Worth confirming this asymmetry is intentional rather than a naming gap, since it breaks the `*Id` convention documented for other entities.
- **`Meeting`/`MeetingBase` has no `mtType`, `mtTags`, or `mtMetadata`.** `RoomBase`, `SessionBase`, and `PresentationBase` all carry these "standard enhancement fields" per the general data-patterns spec. Meeting is the one entity missing them — decide whether to add them or document why Meeting is exempt.
- **`MeetingDataVersion`** (`currentDataVersion?`, `previewDataVersion?`) is defined in `meeting.ts` but never intersected into `Meeting`, `ResolvedMeeting`, or `BaseEnvMeeting` — it's currently unused/orphaned. Decide where it's meant to attach.
- **`RecipeMeeting`** (in [`develop-mock-data/src/recipe-types.ts`](../../../packages/develop-mock-data/src/recipe-types.ts)) diverges from core's `Meeting`: it adds `startDate`/`dayCount` and uses a plain `timezone?: string` instead of `TzConfig`. No conversion exists between the two shapes today — needs reconciliation or explicit scoping of which type is authoritative where.
- **No composed `MeetingWithRooms`/`MeetingWithSessions` type.** Session has `SessionWithRoom`, `SessionWithPres`, etc. for composing children; Meeting has no equivalent — mock-data instead bundles `rooms`/`sessions` alongside (not inside) a meeting via `MockMeetingData`. Decide if a composed type belongs in `core` for consistency, or if external bundling is intentional here.
